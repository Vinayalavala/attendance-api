# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed. "Zone" = the time-zone problem that runs through most of the helpers: shifts and dates are IST, but the starter works on whatever datetime it is given (naive local time or UTC).

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Not `tz_aware`, so PyMongo returns naive datetimes. They cannot be subtracted from aware ones (500) and silently mean "server local time". No server-selection timeout either. | `compute_overtime` raises `TypeError: can't subtract offset-naive and offset-aware datetimes`. | `tz_aware=True` (UTC-aware everywhere), `serverSelectionTimeoutMS=5000`. |
| 2 | `compute_late_minutes` | Zone: `punch_in.replace(hour=h, minute=m)` applies the IST shift time to a UTC/naive datetime. | Shift 09:30, punch 04:35Z (10:05 IST): start becomes 09:30 *UTC*, result is wrong (about -295 min, so 0, instead of 35). | Convert to IST, build the shift start from the attendance date. |
| 3 | `compute_late_minutes` | Grace boundary: `int(seconds/60) > 10`. 09:40:01 gives 10, which is not `> 10`, so it returns 0 (R2 says 10). | Punch at 09:40:01 expects 10. | Compare in whole seconds: `secs > 600`, then `secs // 60`. |
| 4 | `compute_late_minutes` | Ignores overnight shifts and sub-second truncation (R1). Start is taken from the punch's own calendar day. | Shift 22:00-06:00, punch 00:30 on the 7th: should be late 150 against the 6th's 22:00, starter gives 0. Punch 09:40:00.900 must count as 09:40:00. | `attendance_date()` implements R1 incl. overnight; the shift start is built from that date; `ms_to_dt` truncates to the second. |
| 5 | `compute_work_hours` | Python `round()` on a float: banker's rounding plus binary float error (R4 wants half-up). | 32850 s = 9.125 h: starter returns 9.12, expected 9.13. | Integer seconds, `Decimal` quantize `ROUND_HALF_UP`. |
| 6 | `compute_overtime` | No 30-minute minimum (R3); shift end always on the punch date, so overnight shifts are wrong; naive/aware subtraction raises TypeError. | Punch-out 18:45 on a 18:30 shift: starter 15, expected 0. Overnight 22:00-06:00, out 06:40 next day: wrong sign/day. | `shift_end_at()` (adds a day for overnight), floor to minutes, `>= 30` else 0. |
| 7 | `create_employee` | Check-then-insert race. Two parallel creates both pass `find_one`, both insert. No unique index exists. | 20 parallel POSTs of the same emp_code give several 201s. | Unique index on `emp_code`; catch `DuplicateKeyError` and return 409. |
| 8 | `create_employee` / `EmployeeIn` | No validation: emp_code format, email, `HH:MM` patterns, lengths, impossible `joined_on`, `shift_start == shift_end`. | `joined_on: "2026-13-45"`, `shift_start: "9:30"`, `emp_code: "x"` all give 201. | Pydantic constraints from the OpenAPI schema plus a calendar-date check and a model validator; 422. |
| 9 | `create_employee` | `created_at = datetime.now()` is naive local time, and the response returns it as an ISO string. Contract: epoch milliseconds, UTC. | `created_at` is a string in the response; value shifts with the server's zone. | `datetime.now(UTC)` at ms precision, serialised as epoch ms. |
| 10 | `list_employees` | `skip = page * page_size` (page 1 skips the first page). `total` counts the whole collection, ignoring the filter. No sort, so pages are unstable. Page / page_size unvalidated (page 0 or negative gives a negative skip, i.e. a 500; page_size 10 000 allowed). | `?page=1` never returns the first employees; `?department=Sales` shows total of all employees. | `(page-1)*page_size`, `count_documents(q)`, `sort emp_code`, `Query(ge=1)` and `le=100`. |
| 11 | `punch_in` | Unknown employee: `emp` is `None`, then `emp["shift_start"]` is a `TypeError`, a 500 instead of 404. | POST with a made-up emp_code. | `get_employee_or_404`. |
| 12 | `punch_in` | `punched_at` handling: `if body.punched_at` treats 0 as missing; `fromtimestamp(ms/1000)` uses server-local time and keeps microseconds; accepts seconds-sized values (1.7e9 gives 1970), floats and numeric strings. | `punched_at: 1783312500` (seconds) returns 201 with a 1970 date. | `StrictInt` bounded to `[1e11, 4.1e12]`, explicit `is not None`, UTC, truncated to whole seconds. |
| 13 | `punch_in` | Attendance date comes from the server's local date, not IST, and ignores overnight shifts (R1). | Server in UTC, punch at 02:00 IST gets yesterday's date. | `attendance_date()`. |
| 14 | `punch_in` | Check-then-insert race: two simultaneous requests both pass `find_one` and both insert (no unique index). | Parallel identical punch-ins give two 201s and two documents. | Unique index `(emp_code, date)`; `DuplicateKeyError` becomes 409; no read before write. |
| 15 | `punch_in` | `status: str` accepts anything (`ABSENT`, `LEAVE`, `"banana"`). Only PRESENT / WFH / ON_DUTY are allowed here. | `status: "LEAVE"` with a punch-in returns 201. | `Literal["PRESENT","WFH","ON_DUTY"]`; 422 otherwise. |
| 16 | `punch_in` response | Leaks the internal ObjectId as `id`; returns raw datetimes instead of epoch ms; the `doc` dict is mutated by `insert_one`. | Response has `id` and ISO strings for `punch_in`. | `serialize_log()` builds the response from scratch: no `_id`/`id`, ms integers. |
| 17 | `list_attendance` | Loads every matching document into memory and sorts in Python. Slow at 100 000 records; sort has no `emp_code` tiebreak; total is `len(docs)`. | Latency and memory grow with the collection; same-date rows come in arbitrary order. | DB-side `sort(date -1, emp_code 1).skip().limit()` backed by an index; `count_documents` for the total. |
| 18 | `list_attendance` | `page=0` gives a negative slice start (wrong page); `page_size` unbounded; `date_from > date_to` not rejected; dates/status unvalidated; leaks `id`; raw datetimes; legacy docs lack `half_day`/`history` in the output. | `?page=0`, `?date_from=2026-07-10&date_to=2026-07-01`, `?status=x`. | Validated query types, 422 for inverted ranges, `serialize_log` fills defaults. |
| 19 | `/health` | Always returns ok; never touches MongoDB (contract: 503 if the DB does not answer). | Stop mongod and call `/health`. | `admin.command("ping")`, 503 on failure. |
| 20 | module level | No indexes at all, and nothing creates them at startup. | `explain` shows COLLSCAN; the race fixes above are impossible. | `ensure_indexes()` in the lifespan hook: idempotent, retried briefly, never crashes startup. |

**Looked at and judged fine**
- `load_dotenv()`: default `override=False`, so real environment variables win, as the contract requires.
- `db.employees.find(q, {"_id": 0})`: the projection is correct, only the surrounding code was wrong.
- `doc.pop("_id")` after `insert_one`: correct (the insert adds `_id`), though I replaced it with an explicit serialiser.
- Extra/unknown JSON fields (derived fields sent by a client): Pydantic v2 ignores them by default, which is what the contract asks.
- `history: []` on new punch-ins: correct per the data model.
